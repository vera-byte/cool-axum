---
title: 登录鉴权
description: 基于官方 sa-token-rust 的登录、鉴权、权限点
---

cool-axum 使用官方 [sa-token-rust](https://github.com/sa-tokens/sa-token-rust)（`sa-token-plugin-axum`）实现登录认证与权限校验。

## 能力

- 登录签发 token（支持 Redis 共享会话）
- 登出（按 token / 按登录人）
- 登录校验中间件（未登录返回 401）
- 权限点 / 角色管理

## 登录

```bash
curl -X POST http://127.0.0.1:8001/admin/base/open/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'
```

响应：

```json
{
  "code": 1000,
  "data": {
    "token": "e6531587dd6bad6a...",
    "userInfo": { "id": 1, "username": "admin", "name": "超级管理员", "passwordV": 1 },
    "permissions": ["*"]
  }
}
```

登录实现：

- 查 `base_sys_user` 校验用户名 + 密码 + `status=1`
- 密码 **bcrypt** 哈希校验（兼容 cool-admin-go 旧 MD5 数据）
- 同账号 + IP **10 分钟内失败 5 次**临时锁定，防口令爆破
- 统一错误提示，防用户名枚举

## 携带 Token

请求头（二选一）：

```
Authorization: Bearer <token>
sa-token: <token>
```

## 当前用户

```bash
curl http://127.0.0.1:8001/admin/base/comm/userinfo \
  -H "Authorization: Bearer $TOKEN"
```

返回登录人 ID、权限点、角色。

## 登出

```bash
curl -X POST http://127.0.0.1:8001/admin/base/open/logout \
  -H "Authorization: Bearer $TOKEN"
```

## 中间件

```rust
use cool_core::auth::{token_layer, check_login_layer, check_permission_layer};

let app = public_routes
    .merge(protected_routes.layer(check_login_layer()))
    .layer(token_layer(sa_state));   // 最外层：提取 token 注入登录人
```

未登录访问受保护接口：

```json
HTTP/1.1 401 Unauthorized
{ "code": 401, "message": "Authentication error" }
```

## 密码与会话失效

- **新增用户**：`POST /admin/base/sys/user/add`，`password` 自动 bcrypt 哈希入库
- **修改密码**：`POST /admin/base/sys/user/update` 传新 `password`，自动：
  1. 哈希入库
  2. `passwordV + 1`
  3. **吊销该用户全部会话**（旧 token 立即 401）
- 不传 `password` 的更新不会改动密码列

## 权限点

```rust
// 设置（M4 从 base_sys_menu.perms 加载）
cool_core::auth::set_permissions("1", vec!["user:list".into(), "user:delete".into()]).await;
cool_core::auth::set_roles("1", vec!["admin".into()]).await;

// 校验
cool_core::auth::has_permission("1", "user:list").await;
```

也可用 Layer 做路由级权限：

```rust
.layer(check_permission_layer("user:list"))
```

## 多节点会话

配置 `redis.cool` 后，会话写入 Redis：

```
cool:sa-token:sa:token:<token>
cool:sa-token:sa:session:<loginId>
cool:sa-token:sa:permission:<loginId>
```

任意节点登录 / 登出，全集群即时生效（已验证）。

未配置 Redis 时回退内存存储，仅限单机开发。

## 配置

```yaml
modules:
  base:
    auth:
      sso: false
      secret: "cool-base88776655"
      tokenExpire: 36000        # token 有效期（秒）
      refreshExpire: 1296000    # 活跃超时（秒）
```

## 路由级权限校验（authority）

对齐 cool-admin-go `BaseAuthorityMiddleware`：URL 自动映射权限点，与 `base_sys_menu.perms` 比对。

### URL → 权限点

```
/admin/base/sys/menu/add   →  base:sys:menu:add
/admin/dict/type/page      →  dict:type:page
/task/info/list      →  task:info:list
```

规则：

| 场景 | 结果 |
|------|------|
| 超管（userId=1 或 perms 含 `*`） | 放行 |
| `/base/comm/*`、`/base/userinfo` 等 comm 接口 | 仅需登录 |
| 用户 perms 包含 URL 权限点 | 放行 |
| 其他 | **403** `登录失效或无权限访问~` |

菜单权限点支持逗号分隔多值：`base:sys:menu:page,base:sys:menu:list,base:sys:menu:info`。

### 权限管理接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/base/comm/permmenu` | 当前用户权限点 + 菜单树 |
| POST | `/base/comm/refreshPerms` | 改角色后刷新权限到会话 |

```bash
curl http://127.0.0.1:8001/base/comm/permmenu -H "Authorization: Bearer $TOKEN"
# → {"code":1000,"data":{"perms":["base:sys:user:add",...],"menus":[...]}}
```

### 权限来源

登录时从 `base_sys_user_role` → `base_sys_role_menu` → `base_sys_menu.perms` 加载，
写入 sa-token 会话；改角色/菜单后调用 `refreshPerms` 即时生效。

## 超级管理员

- **userId == 1**：无条件放行，无视权限点校验
- **permissions 含 `*`**：同样放行

普通用户仍按 `base_sys_menu.perms` 严格比对。

## 令牌传递（兼容多种方式）

| 方式 | Header |
|------|--------|
| Bearer | `Authorization: Bearer <token>` |
| Raw | `Authorization: <token>` |
| sa-token | `sa-token: <token>` |
| Cookie | `Cookie: satoken=<token>` |

服务端自动归一到 sa-token 会话层，前端无需关心格式。

## 登录响应（TokenResult）

对齐 cool-admin-go：

```json
{
  "expire": 36000,
  "token": "<token>",
  "refreshExpire": 1296000,
  "refreshToken": "<token>",
  "userInfo": { "id": 1, "username": "admin" },
  "permissions": ["*"]
}
```

## 请求日志

每个请求自动：
1. 控制台输出 `method / path / status / cost_ms`
2. 写入 `base_sys_log`（userId / action / ip / params，敏感字段脱敏）

可在后台「请求日志」页面按用户、行为、关键字查询。
