## 是什么

事件总线让**模块之间解耦通信**：一方 `emit` 发出事件，一方注册处理器接收。cool-axum 的事件总线支持**分布式投递**——同一事件可广播给集群所有机器，或随机投递给其中一个。

对齐 cool-admin-midway 的 `@CoolEvent()` / `@Event(name)` 事件框架，并以其 `DistributedEventBus`（Redis Pub/Sub）作为传输层，跨进程、跨机器均生效。

```text
                 ┌───────────────────────────────────────────┐
                 │             cool-axum 集群                 │
   emit/global   │  ┌────────┐   Redis Pub/Sub   ┌────────┐  │
  ─────────────▶ │  │ 节点 A │ ────────────────▶ │ 节点 B │  │
                 │  └────────┘    (channel)      └────────┘  │
                 └───────────────────────────────────────────┘
                        ▲                              │
                        └──────── 本地 handler 分发 ────┘
```

| 特点 | 说明 |
|------|------|
| **本地事件** | `emit` 仅当前进程分发 |
| **分布式广播** | `global_emit(Broadcast)` 广播给集群所有实例（跨机器） |
| **分布式随机** | `global_emit(Random)` 随机投递给一个实例（`SET NX` 保证精确一次） |
| **解耦注册** | 处理器按事件名注册，发送方无需知道接收方 |
| **无 Redis 降级** | 未配置 Redis 时自动回退进程内模式 |

## 系统默认事件

事件名字符串与 cool-admin-midway `EVENT` **逐字一致**：

| 常量 | 事件名 | 说明 |
|------|--------|------|
| `Event::SoftDelete` | `onSoftDelete` | 数据被软删除 |
| `Event::ServerReady` | `onServerReady` | 服务成功启动 |
| `Event::Ready` | `onReady` | 服务就绪 |
| `Event::EsDataChange` | `esDataChange` | ES 数据变更 |

也可使用任意自定义事件名（`&str`），如 `"demo:global"`。

## 注册处理器

处理器 = `Fn(EventData) -> BoxFut` 闭包（对应 `@Event(name)` 标注的方法），在模块 `init()` 时注册：

```rust
use cool_core::event::{Event, EventData, global};

// 模块 init 内（对应 recycle 的 @Event(EVENT.SOFT_DELETE) softDelete 处理器）
if let Some(bus) = global() {
    bus.on(Event::SoftDelete, {
        let svc = recycle_svc.clone();   // 捕获需要的 service
        move |data: EventData| {
            let svc = svc.clone();
            Box::pin(async move {
                if let Ok(rec) = serde_json::from_value(data) {
                    svc.record(rec).await;
                }
            })
        }
    });
}
```

> `EventData` = `serde_json::Value`，对应 TS 的 `...args`；处理器内用 `serde_json::from_value` 反序列化为强类型。
>
> 已构建好的 `Handler`（`Arc` 包装）可用 `on_handler(name, h)` 注册。

## 发送事件

```rust
// 仅本进程
bus.emit(Event::SoftDelete, serde_json::json!({ "table": "demo_item" })).await;

// 广播给集群所有实例（跨进程、跨机器）
bus.global_emit(Event::SoftDelete, data, DeliverMode::Broadcast).await;

// 随机投递给一个实例（精确一次）
bus.global_emit("demo:job", data, DeliverMode::Random).await;
```

### 投递模式

| 模式 | 行为 | 适用 |
|------|------|------|
| `DeliverMode::Broadcast` | 本实例立即执行，其余实例经 Redis 收到后执行（跳过自身，避免重复） | 缓存失效、日志广播 |
| `DeliverMode::Random` | 不预执行，所有实例收到后 `SET NX` 抢占，只有一个执行 | 单点任务、定时作业 |

> **软删除用本地 `emit` 而非 `global_emit`**：回收落库是共享存储，跨机执行会产生重复记录。软删除时框架经 `emit(Event::SoftDelete, …)` 触发，对齐 cool-admin-midway core 的 `coolEventManager.emit(EVENT.SOFT_DELETE, params)`。

## 配置

事件总线在应用启动时由 `app.rs` 装配（构造 + 设为全局 + 启动订阅），Redis 复用 `cool.redis`：

```yaml
redis:
  cool:
    address: "127.0.0.1:6379"
    db: 0
    password: ""
```

未配置 `redis.cool` 时，`global_emit` 自动回退为进程内 `emit`（单机开发无需 Redis）。

`EventBusConfig` 字段：

| 字段 | 默认 | 说明 |
|------|------|------|
| `enabled` | `true` | 关闭后仅进程内生效 |
| `redis_url` | `None` | 连接地址；`None` → 进程内模式 |
| `keys` | `"cool"` | 项目标识，频道隔离（多项目共用 Redis 不串扰） |
| `channel_prefix` | `"cool:event:bus"` | 频道前缀，最终频道 `{prefix}:{keys}` |
| `claim_ttl_secs` | `30` | random 模式抢占锁过期时间 |
| `fallback_local` | `true` | Redis 不可用时是否回退进程内广播 |

## 参考

| API | 说明 |
|-----|------|
| `Event` | 系统默认事件枚举（`as_str()` 取事件名） |
| `DeliverMode` | `Broadcast` / `Random` |
| `EventBus::on(name, f)` | 注册处理器（闭包） |
| `EventBus::on_handler(name, h)` | 注册已构建的 `Handler` |
| `EventBus::emit(name, data)` | 本地分发 |
| `EventBus::global_emit(name, data, mode)` | 分布式投递 |
| `EventBus::start_listener()` | 启动 Redis 订阅（处理器注册后调用） |
| `event::global()` / `init_global()` | 全局单例（无句柄调用点发射） |

- 软删除记录 `SoftDeleteRecord`（`{ table, ids, rows, userId, url }`）经 `Event::SoftDelete` 携带，回收站可据此落库。
- 更多分布式能力见 [分布式](/distributed)。
