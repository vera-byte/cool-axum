## 0.1.0

首个版本：cool-admin-go 完整移植里程碑 M1–M6。

### 核心框架

- Cargo workspace：`cool-config` / `cool-db` / `cool-core` / `cool-auth` / `cool-axum`
- 统一响应体与错误码（1000/1001/51/1003…）对齐 cool-admin-go
- 配置结构对齐 `manifest/config/config.yaml`（camelCase）

### CRUD 引擎

- `CrudService` + `QueryOp` + `crud_router`：add/delete/update/info/list/page 六接口
- 软删除、自动时间填充、唯一键/非空校验、敏感字段剥离
- SQL 构建器：标识符引用、注入防护、排序白名单
- MySQL / PostgreSQL 双支持

### 鉴权

- 官方 sa-token-rust（sa-token-plugin-axum）接入
- 登录 / 登出 / userinfo / 登录校验中间件
- 权限点 / 角色（StpUtil）
- Redis 共享会话（多节点即时生效）

### 业务模块

- base：用户 / 角色 / 菜单 / 部门 / 参数 / 日志 / 三张关联表
- dict：字典类型 / 字典项
- task：任务 / 任务日志
- space：文件 / 文件分类
- demo：示例 CRUD

### 数据库

- autoMigrate（17 表，IF NOT EXISTS）
- 列默认值、AUTO_INCREMENT、保留字引用

### 部署

- Dockerfile 多阶段构建
- docker-compose（mysql + redis + 多实例 + nginx）
- K8s Deployment / Service / HPA
- 跨节点会话共享验证通过

### 文档

- Mintlify 文档站：介绍 / 快速开始 / 配置 / CRUD / 鉴权 / 数据库 / 模块 / 分布式 / 部署 / API / FAQ

## Unreleased · Raft 分布式选主

### 定时任务单点执行
- 新增 `crates/cool-raft`（openraft 0.10 + RocksDB 持久化，HTTP RPC）
- 配置 `raft.{enable,nodeId,selfAddr,dataDir,peers}`；默认关闭（单机任务本地跑）
- 启用后仅**有效 Leader**（角色 Leader 且 quorum 可达）执行任务，防重复调度 / 裂脑
- bootstrap：最小节点 ID 初始化全成员集群；启动失败回退单机

### RocksDB 持久化存储
- `RocksLogStore`：日志 + vote + committed 位点，进程重启可恢复
- `RocksStateMachine`：applied-state（last_log_id + membership），不做 Raft KV
- `raft.dataDir`（默认 `./data/raft`）每节点独立；重启跳过 bootstrap
- 单测覆盖 open/reopen 持久化往返
- **集群冒烟通过**：全量重启 / 杀 Leader 重启均从 RocksDB 恢复 vote·日志·成员，3/3 跳过 bootstrap，term 与 lastLogIndex 连续

### 集群管理 API
- `GET /raft/status` — 节点角色 / Leader / term / peers
- `POST /raft/add-learner` / `POST /raft/change-membership` — 成员管理
- 节点间 RPC：`/raft/vote` / `/raft/append`（免鉴权）

### 文档
- `distributed` 增补 Raft 选主、任务门控、RocksDB 持久化与已知边界
- `configuration` / `api-reference` / `introduction` / README / DELIVERY 同步

## Unreleased · 链路追踪与节点标签

### X-Trace-Id 含节点
- 每请求生成/透传 `X-Trace-Id`，格式 `{nodeLabel}-{hex}`，可直接看出落到哪个节点
- 响应头：`X-Trace-Id` / `X-Node-Id` / `X-Node-Label`，上游链路存 `X-Parent-Trace-Id`
- 识别 `X-Request-Id` / `X-Correlation-Id` / W3C `traceparent`
- 请求日志打印 `trace=` 与 `node=`

### 自定义节点标签
- `server.nodeLabel` 可定制 `X-Node-Label` 与 trace 前缀（如 `bj-node-1`）
- 未配置时默认 `{nodeId}@{port}`

### 转发 Leader 透传链路
- Raft 管理操作非 Leader 时自动 HTTP 转发到 Leader
- 转发携带 `X-Trace-Id` 等链路头
- 响应头返回**客户端原始** `X-Trace-Id`（不被 Leader 新 ID 覆盖）
- 附加 `X-Served-Node` 标注实际处理节点

### 日志含节点与链路
- **所有日志行**固定输出 `node={节点标签}`，多节点可按节点过滤
- 请求日志输出 `trace=`；`base_sys_log.params` 前缀 `trace=` 便于库内检索
- 转发/本地执行 Raft 管理操作均打印 `trace=` 与 Leader 地址

### 日志格式与级别可配
- `logger.format`：`text`（默认，含 `node=`）| `json`（结构化，含 `node` 字段）
- `logger.level`：`trace` / `debug` / `info` / `warn` / `error`，`RUST_LOG` 可覆盖
- 配置说明与 API 文档已补充示例与字段表

### 日志文件输出与按大小轮转
- `logger.file.{path,maxSize,maxFiles}`：写入文件，满 `maxSize` 轮转为 `.1` `.2` …
- `maxFiles` 控制保留份数；`stdout` 可与文件同时输出
- 生产可 `stdout: false` 只写轮转文件

## Unreleased · 分布式全局事件

对齐 cool-admin-midway 事件框架（`@CoolEvent` / `@Event`）+ `DistributedEventBus`（Redis Pub/Sub）。

### 事件总线（`cool_core::event`，方法式 API）
- `event.on(name, handler)` 注册处理器（等价 `@Event(name)`）；`event.on_handler` 注册已构建 `Handler`
- `event.emit` 本进程分发；`event.global_emit` 经 Redis Pub/Sub 跨进程、跨机器投递
- 投递模式：`Broadcast`（广播所有实例）/ `Random`（`SET NX` 抢占，精确一次投递给一个实例）
- 系统默认事件 `Event`（`onSoftDelete` / `onServerReady` / `onReady` / `esDataChange`）字符串值与 TS 逐字一致
- 无 Redis 自动降级为进程内模式；频道 `cool:event:bus:{keys}` 多项目隔离

### 集成
- 软删除经 `notify_soft_delete` → `event.emit(Event::SoftDelete)` 触发（对齐 core `coolEventManager.emit(EVENT.SOFT_DELETE)`）
- 启动装配：构造 + `event.init_global` + `start_listener` + 生命周期事件（`onReady` / `onServerReady`）
- 新增文档页 [分布式事件](/event)
