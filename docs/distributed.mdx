## 架构形态

cool-axum 采用**多节点部署同一单体**：

- 应用**无状态**（会话不落本地内存）
- **Redis** 共享会话 / 权限 / 角色
- **MySQL/PG** 共享数据
- 多实例水平扩展，Nginx / K8s Service 负载均衡

```
                 ┌─────────────┐
   client ──────►│  Nginx/LB   │
                 └──────┬──────┘
            ┌───────────┼───────────┐
            ▼           ▼           ▼
       ┌────────┐  ┌────────┐  ┌────────┐
       │ axum-1 │  │ axum-2 │  │ axum-N │  同一二进制
       └───┬────┘  └───┬────┘  └───┬────┘
           │           │           │
           ▼           ▼           ▼
       ┌────────────────────────────────┐
       │  Redis（会话） + MySQL（数据）   │
       └────────────────────────────────┘
```

## 跨节点会话共享（已验证）

1. 节点 A 登录 → token 写入 Redis
2. 节点 B 携带同一 token → 正常访问
3. 节点 A 登出 → 节点 B 立即 401

Redis 键前缀 `cool:sa-token:`：

```
sa:token:<token>           token → loginId
sa:session:<loginId>       会话数据
sa:permission:<loginId>    权限点
sa:role:<loginId>          角色
```

## 启用条件

`config.yaml` 配置 `redis.cool` 即启用 Redis 会话；未配置回退内存（仅单机）。

```yaml
redis:
  cool:
    address: "127.0.0.1:6379"
    db: 0
```

Redis 连接 3 秒超时自动回退内存并打日志，不阻塞启动。

## 健康检查

`GET /health` 返回 DB / 连接池状态，供 LB 与 K8s 探针使用：

```json
{ "code": 1000, "message": "success", "data": { "database": "up", "pools": 1 } }
```

## Raft 选主：定时任务单点执行

多节点部署时，定时任务若每节点各跑一次会重复调度。cool-axum 通过 **openraft 选主**保证**仅 Leader 执行任务**。

> 边界：Raft 只做**选主与任务门控**，不是分布式 KV。业务数据仍在 MySQL / Redis。

### 启用

```yaml
raft:
  enable: true
  nodeId: 1                          # 本节点 ID（集群内唯一）
  selfAddr: "http://127.0.0.1:8001"  # 本节点 API 地址（供其他节点 RPC）
  dataDir: "./data/raft"             # RocksDB 持久化目录（每节点独立）
  peers:
    - "1:http://127.0.0.1:8001"
    - "2:http://127.0.0.1:8002"
    - "3:http://127.0.0.1:8003"
```

| 项 | 说明 |
|----|------|
| `enable: false`（默认） | 单机模式，任务在本节点直接执行 |
| `enable: true` | 仅 **有效 Leader** 执行任务；其余节点跳过本轮 |
| `peers` | `id:addr` 列表，addr 为该节点 HTTP API 地址 |
| `nodeId` / `selfAddr` | 本节点身份与地址，需与 peers 中自己的条目一致 |
| `dataDir` | RocksDB 落盘目录（日志 / vote / applied-state），默认 `./data/raft` |

各节点配置**同一集群成员表**，`nodeId` / `selfAddr` / `dataDir` 各不相同。首次启动由**最小节点 ID** 的节点一次性 `initialize(全体 voter)` 完成 bootstrap；**重启后从 RocksDB 恢复，自动跳过 bootstrap**。

### 任务门控语义

启用 Raft 后：

1. 调度器初始**禁止执行**（避免 Follower 启动窗口误跑）
2. 后台每秒检查一次领导力，通过后才放行任务循环
3. 「有效 Leader」= **角色是 Leader 且 quorum 可达**（`ReadIndex` 线性一致读屏障，2s 超时）
4. 少数派 / 网络分区中的滞留 Leader **不会**执行任务，防止裂脑双跑

```
Follower/Candidate ──► 跳过本轮任务
Leader + quorum 健康 ──► 执行任务并写 task_log
Leader + 失去多数派 ──► 停止执行（等待重新获选）
```

故障切换：Leader 宕机后其余节点在选举超时（默认 1.5–3s）内选出新 Leader，任务在新 Leader 上继续调度。

### 集群管理 API

| 方法 | 路径 | Body | 说明 |
|------|------|------|------|
| GET | `/raft/status` | — | 节点角色、Leader、term、日志位点、peers |
| POST | `/raft/add-learner` | `{"id":2,"addr":"http://..."}` | 添加学习者（无投票权） |
| POST | `/raft/change-membership` | `{"members":[1,2,3]}` | 变更投票成员 |

Raft RPC（节点间，免鉴权，须开放）：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/raft/vote` | 选举投票 |
| POST | `/raft/append` | 日志复制 / 心跳 |
| POST | `/raft/snapshot` | 快照（暂未实现，返回 501） |

`GET /raft/status` 示例：

```json
{
  "code": 1000,
  "message": "success",
  "data": {
    "nodeId": 1,
    "role": "Leader",
    "leader": 1,
    "isLeader": true,
    "term": 2,
    "lastLogIndex": 12,
    "lastApplied": 12,
    "peers": {
      "1": "http://127.0.0.1:8001",
      "2": "http://127.0.0.1:8002"
    }
  }
}
```

### 扩容

```bash
# 1. 新节点以空 peers / 仅自身启动，加入后：
curl -X POST http://127.0.0.1:8001/raft/add-learner \
  -H 'Content-Type: application/json' \
  -d '{"id":4,"addr":"http://127.0.0.1:8004"}'

# 2. 提升为投票成员（须经 Leader 调用）
curl -X POST http://127.0.0.1:8001/raft/change-membership \
  -H 'Content-Type: application/json' \
  -d '{"members":[1,2,3,4]}'
```

### 持久化存储

Raft 状态落在 `dataDir`（RocksDB）：

```
data/raft/
├── log/    # 日志 + vote + committed 位点（RocksLogStore）
└── sm/     # applied-state：last_log_id + membership（RocksStateMachine）
```

- 进程重启后从磁盘恢复，不丢 vote / 日志 / applied 位点
- **不做 Raft KV**：业务数据仍在 MySQL / Redis
- applied-state 的 Normal 条目只推进 `last_log_id`，不写应用数据

### 重启恢复验证（已冒烟）

三节点集群（`nodeId=1/2/3`，端口 8001–8003，各自 `dataDir`）实测：

| 步骤 | 操作 | 预期 | 结果 |
|------|------|------|------|
| 1 | 首次启动三节点 | 最小节点 ID bootstrap，选出 Leader | ✅ `initialize({1,2,3})`，Leader=1，term=2 |
| 2 | 确认落盘 | `dataDir/{log,sm}` 出现 RocksDB 文件 | ✅ CURRENT / MANIFEST / LOG 等 |
| 3 | **全量 kill → 重启** | 跳过 bootstrap，状态从磁盘恢复 | ✅ 3/3 打日志 `Raft 已初始化，跳过 bootstrap（从持久化状态恢复）` |
| 4 | 对比重启前后 `/raft/status` | term / lastLogIndex / membership 连续 | ✅ term=2、lastLogIndex=1、members{1,2,3} 一致 |
| 5 | **杀 Leader → 重启 node1** | 恢复 vote/日志后重新参选 | ✅ 跳过 bootstrap，`id=1 becomes leader` |
| 6 | 再次全量重启 | 仍不重复 bootstrap | ✅ 3/3 跳过 bootstrap，状态完整 |

恢复日志中的关键状态（`startup begin`）：

```
vote:        Vote { leader_id: {term:2, node_id:1}, committed: true }
log_ids:     [index:0, index:1 (term 2)]
membership:  {1, 2, 3}
→ Raft 已初始化，跳过 bootstrap（从持久化状态恢复）
```

**结论**：进程重启后 Raft 状态（vote / 日志 / applied-state / 成员）从 RocksDB 完整恢复，不会重复 bootstrap。

复现方式：每节点 `COOL_CONFIG=node{i}.yaml cargo run`（或指定二进制），`raft.dataDir` 指到独立目录；`curl :8001/raft/status` 观察 term/leader/lastLogIndex。

### 已知边界

| 项 | 现状 |
|----|------|
| 快照传输 | 入站 `/raft/snapshot` 暂未实现（状态机极小，仅选主；本地快照可构建） |
| 成员变更 | 手动调用管理 API，无自动发现 |
| 启动失败回退 | Raft 启动失败时记 error 并退回单机模式（任务本地执行） |
| dataDir 备份 | 节点本地磁盘；多副本各自持久化，无需共享盘 |

## 无状态约定

- 不在进程内缓存会话 / 权限（交给 Redis）
- 定时任务通过 Raft 选主单点执行（见上文）；未启用 Raft 时每节点各跑
- 文件上传走共享存储（local 挂共享盘 / minio / oss）
